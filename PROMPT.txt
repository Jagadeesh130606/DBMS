# PROJECT IMPLEMENTATION PROMPT
## Research Paper Discovery and Semantic Recommendation System Using Multi-Model Databases

Act as a senior full-stack developer, database architect, and DBMS engineer.

Build a complete, functional, production-quality academic project named:

**Research Paper Discovery and Semantic Recommendation System Using Multi-Model Databases**

Do not create only a frontend prototype. Implement the entire application, including frontend, backend, PostgreSQL, MongoDB, semantic search, SQL operations, authentication, database integration, testing, and documentation.

Do not stop after generating the project structure. Implement every module, connect all components, run the application, test the functionality, and fix errors.

# 1. PROJECT OBJECTIVE

Develop a research paper discovery platform that allows students and researchers to:

- Search for research papers using keywords.
- Search using natural language queries.
- Discover semantically similar research papers.
- Filter papers by author, research area, publication date, and source.
- View complete research paper details.
- Bookmark research papers.
- Maintain search history.
- Explore authors and research areas.
- View citations and related papers.
- Receive personalized research paper recommendations.

The project must demonstrate practical implementation of relational databases, NoSQL databases, SQL queries, database normalization, indexing, transactions, triggers, stored procedures, aggregation, and vector similarity search.

# 3. DATABASE ARCHITECTURE

Use two database systems.

A. POSTGRESQL — RELATIONAL DATABASE

PostgreSQL must store structured and relational information.

Create the following nine tables.

1. USERS

Columns:
- user_id (Primary Key)
- name
- email (Unique)
- password_hash
- role (ADMIN or STUDENT)
- created_at

2. AUTHORS

Columns:
- author_id (Primary Key)
- name
- affiliation
- email

3. RESEARCH_PAPER

Columns:
- paper_id (Primary Key)
- title
- abstract
- doi (Unique)
- publication_date
- citation_count
- source
- created_at

4. RESEARCH_AREA

Columns:
- area_id (Primary Key)
- area_name (Unique)
- description

5. PAPER_AUTHOR

Columns:
- paper_id (Composite Primary Key, Foreign Key)
- author_id (Composite Primary Key, Foreign Key)
- author_order

6. PAPER_AREA

Columns:
- paper_id (Composite Primary Key, Foreign Key)
- area_id (Composite Primary Key, Foreign Key)

7. BOOKMARK

Columns:
- user_id (Composite Primary Key, Foreign Key)
- paper_id (Composite Primary Key, Foreign Key)
- created_at

8. SEARCH_HISTORY

Columns:
- search_id (Primary Key)
- user_id (Foreign Key)
- search_query
- search_type
- search_date

9. CITATION

Columns:
- citing_paper_id (Composite Primary Key, Foreign Key)
- cited_paper_id (Composite Primary Key, Foreign Key)

Add appropriate:
- NOT NULL constraints
- UNIQUE constraints
- CHECK constraints
- Foreign keys
- ON DELETE and ON UPDATE actions
- Composite primary keys
- Appropriate indexes

Ensure that a paper cannot cite itself.

Use normalized relational design and maintain referential integrity.

B. MONGODB — DOCUMENT DATABASE

MongoDB must store flexible and unstructured research-paper content.

Create a collection named `paper_documents`.

Each document should contain:

{
  "paper_id": 1,
  "full_text": "...",
  "sections": [
    {
      "heading": "Introduction",
      "content": "..."
    },
    {
      "heading": "Methodology",
      "content": "..."
    },
    {
      "heading": "Results",
      "content": "..."
    },
    {
      "heading": "Conclusion",
      "content": "..."
    }
  ],
  "references": [
    {
      "title": "...",
      "authors": ["..."],
      "year": 2024,
      "doi": "..."
    }
  ],
  "keywords": ["machine learning", "AI"],
  "metadata": {
    "language": "English",
    "document_type": "Research Article"
  }
}

Use MongoDB for:
- Full research paper content.
- Paper sections.
- References.
- Flexible metadata.
- Document retrieval.
- Aggregation pipelines.

Create indexes for paper_id and relevant searchable fields.

Maintain a consistent relationship between PostgreSQL paper_id and MongoDB paper_id.

Do not duplicate relational data unnecessarily.

C. PGVECTOR — SEMANTIC SEARCH

Enable the PostgreSQL pgvector extension.

Create a separate table named `paper_embeddings`.

Suggested columns:
- embedding_id
- paper_id (Foreign Key)
- embedding vector
- embedding_model
- created_at

Generate embeddings from paper titles and abstracts, with an optional full-text embedding strategy.

Use cosine similarity to find relevant papers.

Implement:
- Embedding generation.
- Embedding storage.
- Similarity search.
- Top-K recommendations.
- Duplicate embedding prevention.
- Embedding updates when paper content changes.

Do not use fake similarity scores or hardcoded recommendations.
